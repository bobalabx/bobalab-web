Fields, required flags, defaults, enum values, lengths and patterns come from the **zod schema** (`src/lib/content/schema.ts`). The generator fails if a field exists on one side only; `tests/unit/cms/parity.test.ts` re-checks `config.yml` against the schema in both directions, including the behaviour of every pattern on boundary samples.

## Commands

```sh
node scripts/cms/build-config.mjs            # regenerate public/admin/* after changing cms/ or the schema
node scripts/cms/build-config.mjs --check    # CI-friendly: exit 1 if out of date (also a unit test)
node scripts/cms/vendor-decap.mjs            # (re)vendor decap-cms@<lock version> with npm pack, verify, record SHA-256
node scripts/cms/vendor-decap.mjs --check    # network: vendored file == npm tarball's dist/decap-cms.js
node scripts/cms/vendor-decap.mjs --version 3.17.2   # bump Decap, then run the tests below
npm run cms:local                            # local demo (decap-server :8081 + next dev :3100, no account)
node scripts/cms/check-backend.mjs [out/admin/config.yml]   # REPLACE-ME left in the backend: warning, error once site.yml launched: true
npx vitest run --config vitest.config.ts tests/unit/cms         # parity, config, hooks, previews, vendor
CMS_VENDOR_CHECK=1 npx vitest run --config vitest.config.ts tests/unit/cms   # + tarball check (network)
npx playwright test tests/e2e/cms-local.spec.ts                 # local demo end to end (needs next dev on :3100)
```

## Production hookup

In `cms/source.mjs`, replace the `REPLACE-ME` worker origin in `backend.base_url` (and check `backend.repo`, `SITE_URL`), run the generator, open a PR. The CSP of `/admin/` is generated from `csp` in the same file. See `docs/SETUP-PRODUCTION.md` (ruleset bypass "for pull requests only", squash merges only, Publish waits for `validate-content`).

## Measured facts (2026-10-20, Chromium, decap-cms 3.17.1)

- **`'unsafe-eval'` is required** in `script-src`: Decap validates its config with Ajv, which compiles with `new Function`; without it Decap stops at "Error loading the CMS configuration" (the e2e spec re-measures this every run). `connect-src` also needs `blob:` (Decap fetches its own object URLs).
- **Richtext marked every entry as changed on open** (its load-time re-serialisation reaches Decap as a change). `cms-widgets.js` re-registers Decap's own control under the same name with a wrapper that drops changes made before the editor touches the field and maps the load-time form back to the stored text: entries now open with "Changes saved" (e2e: "rich-text bodies …"). A real edit still saves the widget's Markdown for the whole body (`-` → `*`, tight lists → loose lists); the `markdown` widget does not, see `docs/change-requests/WP6/3-…`. At a Decap bump, check whether the wrapper is still needed.
- **File/image widgets cannot carry a `pattern`**: a valid `https://` value fails Decap's pattern check and blocks saving, so these fields have none (the validator still checks them).
- Decap keeps cleared optional fields as `""`, which the schema rejects for URLs, dates and DOIs; `cms-hooks.js` removes them before saving.
- Only `dist/decap-cms.js` is vendored. Its lazy chunks (CodeMirror modes for the `code` widget, a WebP encoder for `media_processing`) are not used by this config; rich-text code blocks are turned off for that reason.
- Without manual init, a slow script download let Decap render its default preview before our templates registered (about 1 load in 10); `cms-start.js` fixes it.
- **Publication file names** (`{{fields.authors.0.name}}-{{year}}-{{slug | truncate(28)}}`): Decap templates cannot take a last name, so the first author's full name is used and `{{year}}` is the year the entry is created. The title part is cut at 28 characters so the PI's 26-character name still fits the 60-character limit of `SLUG_PATTERNS.publications`; `cms-hooks.js` re-computes the name Decap will give a new entry (any collection) and blocks the first save with advice when it would break the pattern or the length (validator `E_SLUG`), e.g. a longer first-author name. When the address fits but starts with a multi-word name, or the paper's year is not this year, the first save is held back once with advice (type the last name only); saving again keeps it.
- **Phone widths:** Decap 3.17.1 gives the editor and its top bar `min-width: 800px`, so the page scrolled sideways at 390 px and the account menu was off-screen. Below 800 px `admin.css` shows the form at full width without the preview pane (and without the site link and "Check for preview" in the top bar).
- **Removing a Direction order item threw** (`Invalid keyPath: expected Ordered Collection or Array: ai-at-work`): Decap's `ListControl.handleRemove` calls `metadata.removeIn(<item value>)` for single-field lists that carry relation metadata. `cms-widgets.js` subclasses the list control and hides the metadata from that one call (e2e: "Direction order …"). Re-check at a Decap bump.
- **Lists cannot be reordered with the keyboard in Decap**: the list widget gives dnd-kit only mouse and touch sensors. The same subclass moves an item with the Up/Down arrow keys on its focused handle through Decap's own `onSortEnd`; `cms-a11y.js` names handles ("Reorder “ai-at-work”, item 2 of 4"), describes the keys and replaces the UUIDs in dnd-kit's spoken drag messages. Multi-select tags still reorder by mouse only (remove and re-add as the alternative).
- **The editor kept the previous entry when only the address changed** (after a save, a pasted entry link opened over the old form and Publish wrote the old file). `cms-start.js` reloads the page when the address moves from one entry to a different existing one; `cms-hooks.js` refuses a save whose entry is not the one in the address.
- **Validator-only errors** (`E_AS_OF_MISSING`, `E_STATUS_SOURCE_MISSING`, `E_YEAR_MISSING`, `E_DIRECTIONS_EMPTY`, `E_DIR_ORDER_DUP`) are mirrored as `requiredRules` / `uniqueRules` in `cms/source.mjs`; `tests/unit/cms/hooks.test.ts` runs the validator on the same edits, so a change on one side fails the test until the other follows.
- **Colours**: previews receive Decap's `getCollection`; the direction preview lists the colours of the other live directions, and the second `preSave` listener refuses a colour already in use (the validator warns with `W_COLOR_DUP` before launch and fails with `E_COLOR_DUP` once `site.launched` is true).
- **/admin/ in a frame**: the CSP is a `<meta>` (GitHub Pages sends no headers), where `frame-ancestors` is ignored, so `cms-start.js` does not start Decap inside a frame and shows a link to open it on its own.
