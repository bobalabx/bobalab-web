# Redesign FOUNDATION request 1: the CMS generator loads Archivo, not Fraunces/Inter/Plex

> **Status: APPLIED (integration, 2026-10-24).** The exact patch below, applied to `scripts/cms/build-config.mjs`. `npm run cms:check` reports "up to date"; `tests/unit/cms` passes.

- File(s): `scripts/cms/build-config.mjs` (not owned by FOUNDATION)
- Why: D-13 item 3 replaces the three old font files with one Archivo variable file.
  FOUNDATION deleted `src/fonts/{fraunces,inter,ibm-plex-mono}*.woff2` and added
  `src/fonts/archivo-latin-wdth-normal.woff2`. The generator's hard-coded `FONTS` list still
  reads the deleted files, so `npm run cms:config` / `npm run cms:check` crash, and its
  `buildLogoSvg()` still draws the old cream/brown pearl with a highlight crescent.
- Workaround used (local, removed afterwards): FOUNDATION ran a patched copy of the script
  (exactly the diff below) once, so `public/admin/{config.yml, preview.css, cms-data.js,
logo.svg, fonts/*}` are already regenerated; the old font files in `public/admin/fonts/`
  were deleted. After this patch is applied, `npm run cms:check` reports "up to date".
- Blocking? No for the page packages; yes for CI: until applied,
  `tests/unit/cms/config.test.ts › generated admin files are up to date` and
  `tests/e2e/cms-local.spec.ts › CSP …` (it runs `build-config.mjs --local`) fail with
  "ENOENT … fraunces-latin-wght-normal.woff2".
- Test that proves it: `npm run cms:check` exits 0; `npx vitest run tests/unit/cms`.
