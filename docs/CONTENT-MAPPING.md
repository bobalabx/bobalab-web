# Content mapping: research dataset → site content schema

**For:** WP7 (content migration). **Written by:** WP0, 2026-10-20.
**Source:** `content-dataset.json` (S1, critic-fixed; camelCase; kept _outside_ the repo in the session scratchpad). **Target:** the zod schema in `src/lib/content/schema.ts`; rules in `src/lib/content/validate.ts`.
**Binding inputs:** `docs/DECISIONS.md` D-03…D-06 win over the brief.

This document resolves the critic's "Dataset ↔ §F3 schema mismatch" blocker. Every dataset key is either mapped, or listed as **not imported** with the reason. When a rule below says _question_, add the item to `docs/CONTENT-QUESTIONS.md` (WP7) instead of guessing.

---

## 0. Global rules

| Rule              | Detail                                                                                                                                                                                                                                                 |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| File layout       | `content/{directions,projects,publications,people,news,opportunities}/<slug>.md` = YAML front matter + Markdown body; `content/pages/<page>.yml`; `content/site.yml`. The slug is the **file name**; there is no `slug` field.                         |
| Draft flag (D-03) | `draft: true` unless the row below says otherwise. Default: `draft = (review.status !== "verified")`. **Always draft:** all directions (D-04), all people except the PI (D-06), opportunities without a verified row.                                  |
| `review.*`        | Never imported. `review.status`, `review.label`, `review.notes` drive `draft` and CONTENT-QUESTIONS only.                                                                                                                                              |
| Inferred text     | `summaryInferred: true` → leave `summary` / `in_brief` **empty** (do not import the inferred sentence). `inferredQuestionIdx` → those questions are **dropped** and listed as questions for the PI.                                                    |
| Own words         | Dataset prose (oneLiner, summaries, news bodies) is already S1's paraphrase; import it as is. Never paste abstracts. `in_brief` ≤ 3 sentences.                                                                                                         |
| URLs              | Validator rejects `http://` (E_HTTP_URL). Rewrite `http://` → `https://` when the host serves https (linkedin.com, hdl.handle.net, upenn.edu hosts all do); otherwise drop the link and add a question. Never import a URL listed under `brokenLinks`. |
| Dates             | Strings: `YYYY`, `YYYY-MM` or `YYYY-MM-DD`. Strip parenthetical notes (`"2023-03 (Crossref record created …)"` → `"2023-03"`).                                                                                                                         |
| Unknown           | Leave the field out. Never fill a field with a guess.                                                                                                                                                                                                  |
| Character set     | Keep names as published (e.g. diacritics). `W_NON_LATIN1` warns if a character falls outside the font subset; that is acceptable.                                                                                                                      |
